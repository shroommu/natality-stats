# Natality Stats - AI Agent Guidelines

This document serves as a comprehensive developer and context guide for AI agents operating on the `natality-stats` repository. All agents must thoroughly read, understand, and adhere to the guidelines, architectures, and verification workflows outlined below.

## 🚨 CRITICAL DIRECTIVE: Check for Human-Initiated Changes

Before proposing, drafting, or committing any modification to any file in this repository, **you must verify whether the file has human-initiated changes.** Agent edits must never blindly overwrite or silently revert custom styling, helper logic, or refactorings introduced by human developers.

### Verification Protocol
1. **Analyze Local State:** Execute `git status` and `git diff` to identify any uncommitted human modifications in the current workspace.
2. **Review Edit History:** Use `git log -n 5 --patch -- <file_path>` (or a similar tool) to review the most recent commits. Look for commit messages, author information, and changes to understand the rationale behind recent edits.
3. **Inspect Content For Human Annotations:** Before writing or editing, read the entire file using the appropriate retrieval tool. Look out for inline comments, custom notes, custom typing abstractions, layout adjustments, or `TODO` annotations written by human authors.
4. **Merge Harmoniously:** Align and integrate agent code to mimic the style, layout patterns, and architectures implemented by human contributors. If a conflict or ambiguity arises between the human-implemented design and the requested feature, **halt and query the user** for confirmation.

## Project Overview & Architecture

`natality-stats` is an interactive dashboard and statistical analysis platform exploring U.S. pregnancy outcomes and birth data using the CDC's 2021–2024 public natality datasets. It consists of three tightly coupled but separate folders:

```
natality-stats/
├── frontend/           # Next.js Web Dashboard (App Router)
├── backend/            # Flask Inference API for ML Predictions
└── dev/                # Data Engineering & Offline Model Pipelines
```

### 1. Frontend (`/frontend`)
* **Technology Stack:** Next.js 16 (App Router), React 19, TypeScript, Material UI v9 (`@mui/material`), Tailwind CSS v4, and Chart.js via `react-chartjs-2`.
* **Important Paths:**
  * `frontend/app/` - App Router page layouts and top-level pages (e.g., `/`, `/vbac`, `/down-syndrome`).
  * `frontend/charts/` - Custom visualization components partitioned by topic (`vbac/`, `down_syndrome/`).
  * `frontend/components/` - Global layout and wrapper components (`AppHeader`, `YearToggle`, `Tabs`, `AppThemeProvider`).
  * `frontend/hooks/` - Data fetching hooks (`useChartJson`, `useSummaryStats`) reading from aggregated public datasets.
  * `frontend/public/data/` - Static yearly JSON aggregates generated by the offline pipeline.
  * `frontend/tests/` - Visual and component tests written in Vitest and React Testing Library.

### 2. Backend (`/backend`)
* **Technology Stack:** Flask, Flask-CORS, Pandas, Scikit-learn, Cloudpickle, XGBoost (CPU version).
* **Core Responsibilities:** Serves model inference endpoints to compute probabilities for clinical VBAC success and Down Syndrome indicators.
* **Important Paths:**
  * `backend/app.py` - Core web application exposing `/api/health`, `/api/predict-vbac`, and `/api/predict-down-syndrome`.
  * `backend/models/` - Dynamic model weights and preprocessor pipelines saved as binary pickle (`.pkl`) artifacts.
  * `backend/tests/` - Comprehensive unit and route test suite evaluated via `pytest`.
  * `backend/vercel.json` - Serverless build configuration targeting `@vercel/python` and `app.py`.

### 3. Offline Data Pipeline (`/dev`)
* **Technology Stack:** Jupyter Notebooks, Pandas, PyArrow, Scikit-learn, Imbalanced-learn, TensorFlow, XGBoost.
* **Core Responsibilities:** Automates ETL processing of raw CDC fixed-width data text files, handles class-imbalance processing, trains ML classification estimators, and outputs the year-over-year JSON data aggregates consumed by the frontend charts.
* **Important Paths:**
  * `dev/notebooks/` - Explanatory notebooks walking through ingestion, cleaning, feature selection, and modeling.
  * `dev/pipelines/` - Automated ETL pipelines: `transform_and_clean_from_raw.py` and `generate_chart_json_files.py`.
  * `dev/models/` - Preprocessor configurations and model files.

## Core Operational Guidelines

Agents must strictly honor the following environment and developmental practices:

### 1. Style & Framework Adherence
* **Typing:** Write strictly typed TypeScript code. Do not use `any` bypasses or suppress type errors with compiler-ignore comments.
* **Styling:** Follow the existing blend of MUI v9 components and Tailwind CSS v4 styling rules. Keep components highly accessible and visually polished.
* **Python Standards:** Format Python code to standard PEP 8 spacing (e.g. using Ruff or Black defaults) with clear, explanatory docstrings.

### 2. File Path Handling
* Always utilize fully qualified absolute paths when referencing, reading, or writing files via developer tools (e.g., `/home/akrucken/dev/natality-stats/frontend/package.json` rather than relative paths).

### 3. Comments & Documentation
* Write comments sparingly.
* Focus on *why* a complex logic branch or mathematical/data transformation is performed, rather than *what* is being done.
* Do not speak to the user or summarize your file updates via comments in the modified source files.

### 4. Code Quality & Safety
* **No Secrets:** Never introduce hardcoded credentials, API keys, or private system keys.
* **Revert Prevention:** Do not roll back or revert existing, stable functionality unless explicitly requested by the user.

## Development & Verification Workflows

Before declaring any task completed, you must execute validation commands in the appropriate directory to guarantee that dependencies, formats, type checks, and tests remain green.

### Frontend Validation Workflow

Always execute these commands inside the `/frontend` directory:

```bash
# 1. Install dependencies securely
npm install

# 2. Run the test suite (Vitest + JSDOM)
npm run test

# 3. Perform static lint checks and type verification
npm run lint
npm run build
```

### Backend Validation Workflow

Always execute these commands inside the `/backend` directory:

```bash
# 1. Activate the python virtual environment
source .venv/bin/activate

# 2. Execute tests with pytest
pytest tests/
```

### Data Pipeline Validation Workflow

Always verify your changes against standard pipeline formats:

```bash
# 1. Run pipeline scripts to ensure JSON schemas match frontend requirements
python dev/pipelines/main/generate_chart_json_files.py
```
